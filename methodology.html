Asset Classification Methodology

Automated matching of asset registers to standardised classification systems
Intelligent
Matching Engine
This document outlines the methodology used to automatically match assets in a register against one or more standardised classification systems. The engine applies multiple independent scoring signals, cross-system validation, and statistical calibration to produce ranked, confidence-graded results — enabling classification at scale without manual lookup.
Process Workflow
1
Data Ingestion & Validation
The asset register (CSV or Excel) and one or more classification system tables are loaded and validated. Required fields are confirmed, column names are standardised, and data quality diagnostics are generated — flagging missing high-value fields such as description or technical_specs that would reduce match accuracy. Duplicate asset IDs are detected and reported.
2
Text Enrichment & Normalisation
Each asset and each classification entry is converted into a unified text representation. Asset fields are combined with field-level importance weighting — the asset name and type receive greater emphasis than free-text notes. Domain acronyms (e.g. SCATS, CCTV, VMS, HPS) are automatically expanded to their full technical terms, ensuring semantic alignment between abbreviated asset descriptions and fully-worded classification entries. Text is then normalised and tokenised. Where classification tables include a hierarchy (parent codes), child entries inherit the vocabulary of their parent categories, improving recall for specific leaf-level classifications.
3
Multi-Signal Similarity Scoring
Every asset is scored against every classification entry using three independent signals. Each signal captures a different dimension of similarity, making the combined result robust to gaps in any single dimension. Weights are automatically tuned based on the asset domain.
A — Semantic Overlap
Full-text conceptual alignment
B — Domain Hierarchy
Category & subcategory match
C — Keyword Precision
Shared technical vocabulary
D — Semantic Embedding
Deep language similarity (ML mode)
4
Calibration, Ranking & Cross-System Validation
Raw scores are calibrated per classification system to a normalised 0–100 scale, ensuring that confidence thresholds remain consistent regardless of how many classification entries a system contains. Results are ranked 1st, 2nd, and 3rd per asset per system. Where multiple classification systems are used, a cross-system agreement check determines whether each system independently reached the same domain conclusion. This agreement signal is incorporated into the composite confidence score, adding a layer of validation beyond any single system's score.
5
Results Output & Review Prioritisation
Results are written to a colour-coded Excel workbook, a plain CSV, and a structured summary report. Every match includes a plain-English reasoning statement explaining why it was chosen. A composite confidence score consolidates all signals into a single priority indicator, enabling review queues to be sorted so the lowest-confidence results are triaged first.
Confidence Tiers
70+
High — Accept with brief check. All scoring signals agree and cross-system validation confirms the domain. The match is reliable.
45–69
Medium — Review before accepting. Primary signal is positive but secondary signals are partial. Compare the 1st and 2nd ranked matches.
<45
Low — Manual classification required. Insufficient signal strength across all dimensions. Typically caused by minimal asset description data.
What Each Result Contains
  • Matched code & name — the classification entry selected
  • Match rank — 1st, 2nd, or 3rd best candidate
  • Similarity score — system-level calibrated score (0–100)
  • Composite confidence — multi-signal priority indicator
  • Confidence flag — high / medium / low (colour-coded in Excel)
  • Reasoning — plain-English explanation of the match
  • Score breakdown — contribution of each scoring signal
Design Principles
⚙️
No Training Data Required
Matching is entirely driven by the content of your register and classification tables — no labelled examples or model training needed.
🔒
Data Stays Local
All processing runs on-premises or in your own environment. Asset data is never transmitted to external services.
🔄
Any Classification System
Works with UNICLASS, ISO, AUSTROADS, agency-specific codes, or any structured code list — no system-specific configuration required.
📈
Scales to Any Register Size
Vectorised batch processing handles thousands to hundreds of thousands of assets without per-row performance degradation.
